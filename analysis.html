Vấn đề kỹ thuật
Mỗi log_event() mở 1 SQLite connection mới → ~4 giây overhead/ca làm việc
Batch status gọi provider API cho từng task pending → O(n) API calls, lãng phí quota
Poll interval cố định 3s → 95%+ requests vô ích khi video đang render
Không có index trên tasks.staff_id, activity_logs.created_at → query slow
GUI calls API synchronously → UI freeze khi backend chậm
Không có WAL mode → reader blocks writer, writer blocks reader
Log file không rotate → sau 3 tháng hàng chục MB, không readable
Vấn đề kiến trúc
Desktop-only: mỗi user cần cài .venv, Python, config — khó onboard
Multi-user = chạy nhiều instance → không share state, data silo
Không có real-time updates giữa users (QC approve xong, staff không biết ngay)
Session data trong RAM → crash = mất hết trạng thái workspace
Không thể access từ xa / remote work
Code PyQt6 nặng (~2000 LOC main_window.py) → khó maintain, khó test
Encoding lỗi tiếng Việt ở nhiều màn hình

Risk Matrix – Khi làm lại
🔴 Cao – Migration data
12 bảng SQLite → 8 bảng PostgreSQL. Cần script migrate + verify từng record. Chạy song song 1 tuần.
🟡 Trung – Provider downtime
KIE/PiAPI có thể 402/503. Circuit breaker + fallback key rotation đã có – cần giữ nguyên logic.
🟡 Trung – User training
Staff quen với PyQt6 GUI. Cần training buổi, hướng dẫn + demo. Browser UX dễ hơn → adoption nhanh.
🟢 Thấp – Telegram integration
Logic Telegram đã ổn định. Giữ nguyên Bot token, chỉ thay endpoint URL từ localhost → domain mới.
